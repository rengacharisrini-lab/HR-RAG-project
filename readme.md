# HR Support Chatbot (RAG-Based)

## Overview

This project implements a **Retrieval-Augmented Generation (RAG)** based **HR Support Chatbot** that answers employee questions using official company HR documents.

The chatbot is designed to:

* Provide **accurate, policy-aligned answers**
* Prevent hallucinations by grounding responses in company PDFs
* Support **context-aware follow-up questions**
* Be easily extendable to production-grade HR systems

---

## Key Features

* **PDF-based Knowledge Source**
  Uses company HR policy documents such as:

  * Welcome & company overview
  * Onboarding process
  * Code of conduct
  * Compensation & benefits
  * Leave & time-off policies
  * IT usage & security policy
  * Workplace safety guidelines

* **Retrieval-Augmented Generation (RAG)**
  Answers are generated by combining:

  * Semantic search over HR documents
  * Large Language Model (LLM) reasoning

*  **Context-Aware Conversations**
  Supports follow-up questions by maintaining chat history.

* **Hallucination Control**
  If information is not present in HR documents, the chatbot explicitly says:

  > “I’m not sure based on current HR policies.”

* 💻 **Streamlit UI**
  Simple chat interface suitable for demos and internal tools.

## Architecture

```
Employee Question
      ↓
Embedding (text-embedding-3-small)
      ↓
Vector Similarity Search (FAISS)
      ↓
Relevant HR Policy Chunks
      ↓
Prompt Augmentation
      ↓
LLM Answer (gpt-4o-mini)
```

## PDF Ingestion (One-Time Step)

This step converts HR PDFs into vector embeddings.

```bash
python ingest.py
```

What this does:

* Loads all PDFs from `data/`
* Splits them into semantic chunks
* Generates embeddings using OpenAI
* Stores vectors locally using FAISS

## Memory Handling

* Chat history is stored in Streamlit session state
* Previous turns are included in the prompt to support follow-ups
* Retrieval is always performed using the **latest question only** to avoid noise

---

## Design Principles

* **LLM does not act as the source of truth**
  HR documents are the authority.

* **Retrieval before generation**
  Answers are grounded in retrieved policy text.

* **Fail-safe behavior**
  The chatbot refuses to answer when information is missing.

---

## Limitations

* No role-based access control 
* No document citations per answer
* Local FAISS storage (not distributed)

## Deploying to Google Cloud Run

This project can be containerized with the included **`Dockerfile`** and deployed to
**Cloud Run**. The prebuilt FAISS index (`hr_faiss_index/`) and the source PDFs
(`documents/`) are copied into the image, so no ingestion step is needed at startup —
the container serves the Streamlit UI directly.

### 1. Store your OpenAI key as a Secret Manager secret (don't bake it into the image)

```bash
gcloud secrets create hr-chatbot-openai-key --replication-policy="automatic"
printf "sk-..." | gcloud secrets versions add hr-chatbot-openai-key --data-file=-
```

Grant your Cloud Run runtime service account access:

```bash
gcloud secrets add-iam-policy-binding hr-chatbot-openai-key \
  --member="serviceAccount:YOUR_PROJECT_NUMBER-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

(If you use LangSmith tracing, create a second secret for `LANGCHAIN_API_KEY` the same way.)

### 2. Build and push the image

```bash
gcloud auth configure-docker
docker build -t gcr.io/YOUR_PROJECT_ID/hr-support-chatbot:latest .
docker push gcr.io/YOUR_PROJECT_ID/hr-support-chatbot:latest
```

Or skip local Docker entirely:

```bash
gcloud builds submit --tag gcr.io/YOUR_PROJECT_ID/hr-support-chatbot:latest
```

By default the image runs `app_with_memory.py` (the context-aware, recommended version). To
ship the no-memory version instead, build with:

```bash
docker build --build-arg STREAMLIT_APP=app.py -t gcr.io/YOUR_PROJECT_ID/hr-support-chatbot:latest .
```

### 3. Deploy

**Option A — one-line deploy:**

```bash
gcloud run deploy hr-support-chatbot \
  --image gcr.io/YOUR_PROJECT_ID/hr-support-chatbot:latest \
  --region us-central1 \
  --platform managed \
  --allow-unauthenticated \
  --set-env-vars MODEL=gpt-4o-mini,OPENAI_API_BASE=https://api.openai.com/v1,LANGCHAIN_TRACING_V2=false \
  --set-secrets OPENAI_API_KEY=hr-chatbot-openai-key:latest
```

**Option B — declarative, via `service.yaml`:**

1. Edit `service.yaml` and replace `YOUR_PROJECT_ID` with your actual GCP project ID.
2. Deploy:

```bash
gcloud run services replace service.yaml --region=us-central1
```

3. (First deploy only) allow public access, if desired:

```bash
gcloud run services add-iam-policy-binding hr-support-chatbot \
  --region=us-central1 \
  --member="allUsers" \
  --role="roles/run.invoker"
```

### 4. Open the deployed app

```bash
gcloud run services describe hr-support-chatbot --region=us-central1 --format='value(status.url)'
```

Open the printed URL in a browser — it's the same Streamlit chat UI, running on Cloud Run.

### Notes

- **Secrets**: `.env` is excluded from the image via `.dockerignore`. Always pass
  `OPENAI_API_KEY` (and any other secret) through Secret Manager / `--set-secrets`, never
  commit or bake it in. The `.env` in this project folder is for **local runs only**.
- **Rotate exposed keys**: if the `.env` bundled in this project ever left your machine
  (e.g. was committed to a public repo or shared), treat those keys as compromised and
  rotate them in the OpenAI/LangSmith dashboards.
- **State**: Streamlit's `st.session_state` chat history lives in-memory per container
  instance. If Cloud Run scales to multiple instances, a user's conversation isn't shared
  across them; each browser session sticks to whichever instance handled its first request
  as long as it stays warm.
- **Updating the knowledge base**: if you add/change PDFs in `documents/`, rerun
  `python ingest.py` locally to regenerate `hr_faiss_index/`, then rebuild and redeploy the
  image so the new index is baked in.
